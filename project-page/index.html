TL;DR. HaloDiffusionLLM trains autoregressive (AR), absorbing-state masked diffusion, block diffusion, and discrete flow matching language models on the same backbone (LGT transformer, 384-d, 16 layers), the same data (WikiText-2), and the same evaluation — making paradigm differences directly comparable.
  • Problem: Paradigm comparison papers typically differ in architecture, scale, data, and evaluation simultaneously — making it impossible to isolate what drives performance.
  • Method: One shared LGT backbone, one dataset, one CLI. A single YAML field (variant:) selects the paradigm. Only the loss function, attention mask, and sampling procedure change.
  • LGT backbone: Local-Global Transformer with dual RoPE — local-window heads capture short-range syntax, global heads capture document structure. Designed for bidirectional models.
  • Visualiser: hale-llm-viz renders a GIF of block diffusion unmasking tokens block by block in real time.
  • Built on: HaleBlocks plugin registries — each paradigm is a registered plugin; the training loop is shared.

Problem Statement

Discrete generative models for text have seen rapid paradigm proliferation — autoregressive transformers, masked diffusion language models (MDLMs), block diffusion, and discrete flow matching all claim advantages in quality, diversity, or controllability. But comparing them is confounded:

Different architectures: AR models use GPT-style causal transformers; diffusion models typically use BERT-style bidirectional encoders. Performance differences could come from the architecture, not the paradigm.
Different scales and data: Published results often compare models of different sizes trained on different corpora. Small differences in data cleaning can dominate paradigm-level effects.
Different evaluation protocols: Token-level perplexity, sequence-level BLEU, and generation diversity are not directly comparable across paradigms with different factorisation assumptions.

HaloDiffusionLLM removes all these confounds: one backbone, one dataset, one CLI, one evaluation script. Observed differences can only come from the generation paradigm.

Method

  1. Shared LGT backbone

    The Local-Global Transformer (LGT) uses two types of attention heads within each layer: local heads (window size $w$, local RoPE with higher frequency) attend only to the nearest $w$ tokens; global heads attend to the full sequence (global RoPE with lower frequency). Their outputs are concatenated and projected back to dimension $d$.

    LGT is used for all non-autoregressive paradigms because bidirectional models benefit from both local syntactic patterns and global document structure. AR uses a standard GPT-style transformer (all-global, causal mask).

    ★ Why LGT for diffusion? Fully global attention on long sequences is quadratic; pure local attention loses document coherence. LGT gives O($S \cdot w$) local cost plus O($S^2 / w$) global cost — subquadratic total at typical $w$ values.

  2. Autoregressive (reference baseline)

    Standard next-token prediction: $\mathcal{L}_\text{AR} = -\sum_t \log p_\theta(x_t \mid x_{<t})$. Causal attention mask. Sampling: temperature, top-$k$, top-$p$ nucleus. Used as the reference baseline — all other paradigms are measured relative to AR perplexity.

  3. Masked diffusion (absorbing state)

    A noise process independently masks each token with probability $m(t)$ at noise level $t \in [0,1]$, replacing it with a special [MASK] token. The model predicts all masked positions in parallel using bidirectional attention. Loss is reweighted by $1/m(t)$: $\mathcal{L}_\text{MD} = -\mathbb{E}_t \frac{1}{m(t)} \sum_{i: x_t^i = \text{MASK}} \log p_\theta(x_i \mid x_t)$. Sampling follows MDLM: unmask the highest-confidence fraction of tokens at each step.

  4. Block diffusion

    The sequence is split into fixed-size blocks. Training samples a random block $k$; the prefix $x_{1:kB}$ is provided as committed context via a block-causal mask, and the current block $x_{kB:(k+1)B}$ is fully masked. The model denoise the active block with bidirectional attention within the block, conditioned on the causal prefix. Sampling proceeds left-to-right over blocks, running $T$ diffusion steps within each block before committing it.

    ★ Best of both worlds: Block diffusion inherits the left-to-right consistency of AR (each block conditions on all prior text) and the parallel generation of diffusion (tokens within a block are generated jointly, enabling richer intra-block dependencies).

  5. Discrete flow matching

    Define a straight-line interpolation in the probability simplex: $p_t(y) = (1-t) p_0(y) + t p_1(y)$ where $p_0$ is a uniform distribution and $p_1$ is the data distribution. The model learns the velocity field $v_\theta(x_t, t)$ that generates a straight-line probability path from uniform to data. Loss: $\mathcal{L}_\text{FM} = \mathbb{E}_{t,x_0,x_1}\|v_\theta(x_t, t) - (p_1 - p_0)\|^2$. Inference integrates the ODE with Euler steps.

Limitations & Ethical Considerations

Small scale

WikiText-2 only

All experiments use the small WikiText-2 corpus (2M tokens). Conclusions may not transfer to larger-scale training. Scaling experiments (WikiText-103, C4) are planned.

Pending

No perplexity table yet

The cross-paradigm perplexity comparison (the main claim of the repo) has not been finalised. The GIF visualisation is qualitative only.

Open

Sampling quality vs. speed

Diffusion and flow matching require multiple forward passes at inference; AR requires one. Wall-clock time per sample is not yet measured across paradigms.

Stub

MTP variant

The multi-token prediction (mtp) variant is a stub with a single head. Multiple independent heads are not yet implemented.

Ethics

Text generation risks

All four paradigms can generate fluent text. Models trained on web corpora inherit corpus biases. This repo is a research comparison framework, not a production text generator.
