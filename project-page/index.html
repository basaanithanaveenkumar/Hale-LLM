HaloDiffusionLLM: Generative Paradigm Comparison on a Shared Transformer Backbone

One small transformer backbone, four generation paradigms. Swap between autoregressive, masked diffusion, block diffusion, and discrete flow matching with a single YAML key.

Code Docs
TL;DR. uv run hale-llm-train --config configs/block_diffusion/small.yaml — a 384-d, 16-layer LGT backbone trains in any of four paradigms. hale-llm-viz writes a GIF showing block diffusion unmasking tokens block by block in real time.

Abstract

The field of discrete generative models is split between several competing paradigms — autoregressive token prediction, absorbing-state masked diffusion, block diffusion (AR across blocks, diffusion inside each block), and discrete flow matching — whose training and inference dynamics differ substantially. Comparing them fairly requires holding the architecture, backbone, data, tokenizer, and evaluation code constant.

HaloDiffusionLLM provides exactly this: a single small transformer backbone (LGT or GPT-style, 384-d, 16 layers, 8 heads) trained on WikiText-2 in each of the four paradigms via a one-line YAML switch. A shared CLI (hale-llm-train, hale-llm-sample, hale-llm-eval, hale-llm-viz) drives all paradigms identically. The repository is built on HaleBlocks and registers each paradigm as a plugin.

Highlights

One YAML key, four paradigms

variant: autoregressive | diffusion | block_diffusion | flow_matching — everything else stays the same. No code changes needed to switch.

LGT backbone

Local-global transformer with dual RoPE: short-range local attention heads + long-range global attention heads. Better suited to bidirectional diffusion than standard GPT.

Block diffusion

AR across blocks, diffusion inside each block. Tokens unmask in the active block while committed tokens stay fixed — animated in real time by hale-llm-viz.

Discrete flow matching

Straight-line interpolation in the token probability simplex, analogous to continuous flow matching, but operating over the discrete token distribution.

Live visualisation

hale-llm-viz writes a GIF: prompt in steelblue, committed tokens in orange, the active block in black on a light overlay — decoding made visible.

Plugin architecture

Each paradigm registers with @register_model, @register_loss, @register_sampler. Adding a new paradigm requires no edits to the shared core.

Quick start

git clone https://github.com/basaanithanaveenkumar/HaloDiffusionLLM && cd HaloDiffusionLLM
uv sync && uv sync --extra dev
uv run pytest tests/unit -q
# Train block diffusion (MPS / CUDA / CPU via device: in YAML)
uv run hale-llm-train --config configs/block_diffusion/small.yaml --no-resume --viz

# Sample, eval and write visualisation GIF from latest checkpoint
uv run hale-llm-sample --config configs/block_diffusion/small.yaml
uv run hale-llm-eval   --config configs/block_diffusion/small.yaml
uv run hale-llm-viz    --config configs/block_diffusion/small.yaml

# Monitor training
tensorboard --logdir data/experiments
# Switch to masked diffusion — nothing else changes
uv run hale-llm-train --config configs/diffusion/small.yaml --no-resume
